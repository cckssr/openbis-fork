### 4. Implementation details leaked into public API

Remove these parameters from all public methods. Handle internally:

- `only_data` — always return entity objects, never raw dicts
- `raw_response` — move to internal `_` methods if needed
- `use_cache` — transparent caching, no user control
- `attrs` — absorbed into `properties` filter (see §API Design)

### SearchResult (`types/results.py`)

```python
from dataclasses import dataclass
from typing import Generic, TypeVar, Iterator

T = TypeVar("T")

@dataclass
class SearchResult(Generic[T]):
    """Iterable result container with total count for pagination awareness."""
    _items: list[T]
    total_count: int

    def __iter__(self) -> Iterator[T]: return iter(self._items)
    def __len__(self) -> int: return len(self._items)
    def __getitem__(self, index: int) -> T: return self._items[index]
    def __bool__(self) -> bool: return bool(self._items)
    def __repr__(self) -> str: ...
```

## Phase 3 – API Design

### Method naming convention

| Pattern                  | Semantics                                          | Return type            |
|--------------------------|----------------------------------------------------|------------------------|
| `get_object(id)`         | Single entity by perm_id or identifier             | `Object \| None`       |
| `get_object_or_raise(id)`| Single entity; raises `NotFoundError` if absent    | `Object`               |
| `search_objects(**kw)`   | Filtered search, paginated                         | `SearchResult[Object]` |
| `iter_objects(**kw)`     | Lazy paginated iterator (auto-fetches next pages)  | `Iterator[Object]`     |
| `new_object(type, **kw)` | Constructs unsaved entity                          | `Object`               |
| `.save()`                | Persists the entity to openBIS                     | `None`                 |
| `.delete(reason)`        | Deletes the entity                                 | `None`                 |

Apply the same pattern for `collection`, `dataset`, `space`, `project`.

### Canonical method signatures

All public methods use **keyword-only args** after the first positional (the identifier).
No bare `**kwargs` in public API.

### PropertyBag — entity properties access

Entities expose properties through a `PropertyBag`, not raw dicts or DataFrames:

```python
class PropertyBag(MutableMapping[str, Any]):
    """Dict-like access to openBIS entity properties. Marks entity dirty on write."""
    def __getitem__(self, key: str) -> Any: ...
    def __setitem__(self, key: str, value: Any) -> None: ...  # marks entity dirty
    def __delitem__(self, key: str) -> None: ...
    def __iter__(self) -> Iterator[str]: ...
    def __len__(self) -> int: ...
    def to_dict(self) -> dict[str, Any]: ...
    def __repr__(self) -> str: ...

# Usage:
obj.props["FORMULA"]           # get
obj.props["FORMULA"] = "H2O"   # set (entity is now dirty, call .save())
"FORMULA" in obj.props         # contains
```

```python
from pybis.entities.object import Object as _Object

def Sample(*args: Any, **kwargs: Any) -> _Object:
    warnings.warn(

        DeprecationWarning, stacklevel=2,
```

## Phase 5 – Docstrings

Google-style for all public classes, methods, and functions.
Include `Args`, `Returns`, `Raises` where non-trivial.

```python
def search_objects(self, *, type: str | None = None, ...) -> SearchResult[Object]:
    """Search for Objects matching the given criteria.

    Args:
        type: Filter by ObjectType code (e.g. ``"MOLECULE"``).
        space: Filter by Space code.
        collection: Filter by parent Collection perm_id or identifier.
        properties: Filter by property values; all must match (AND logic).
            Example: ``{"FORMULA": "H2O", "STATUS": "ACTIVE"}``.
        with_parents: Include parent relationships in result objects.
        count: Maximum number of results to return (default: 25).
        start_with: Pagination offset (default: 0).
        fetch: Which related data to eagerly load.

    Returns:
        A SearchResult containing matched Objects and the total count
        (which may exceed ``len(result)`` if paginated).

    Raises:
        AuthenticationError: Session is not authenticated.
        ConnectionError: openBIS server is unreachable.
    """
```

```python
        "permId": {"permId": kwargs.pop("perm_id", "20240101-1"), "@type": "as.dto.sample.id.SamplePermId"},
        "identifier": {"identifier": kwargs.pop("identifier", "/SPACE/PROJ/OBJ-1"), "@type": "..."},
        "code": kwargs.pop("code", "OBJ-1"),
        "type": {"code": kwargs.pop("type", "UNKNOWN")},
        "properties": kwargs.pop("properties", {}),
    }
    defaults.update(kwargs)
    return defaults

def make_search_response(objects: list[dict], total_count: int | None = None) -> dict:
```

## Phase 8 – Automatic Identifier Classification

### Problem

The current codebase has two untyped utility functions (`is_identifier`, `is_permid`)
that are used inconsistently across methods. `get_object` takes a positional
`sample_ident` with no type information. Search methods expose three separate params
(`perm_id`, `identifier`, `code`) that the caller must choose between manually.

### Solution: `utils/identifier.py`

```python
from __future__ import annotations
import re
from typing import Literal, NamedTuple

IdentifierKind = Literal["perm_id", "identifier", "code"]

# Matches existing openBIS permId format: 20160817175233002-331 or 20240101-1
_PERM_ID_RE = re.compile(r"^\d{8,}-\d+$")
_IDENTIFIER_RE = re.compile(r"^/")

def classify_id(value: str) -> IdentifierKind:
    """Classify a string as a perm_id, full identifier, or bare code.

    Rules (in order):
    - Starts with '/'            → identifier  (e.g. /SPACE/PROJECT/CODE)
    - Matches \\d{8,}-\\d+        → perm_id    (e.g. 20240101-1)
    - Anything else              → code        (e.g. MY-OBJECT)
    """
    s = value.strip()
    if _IDENTIFIER_RE.match(s):
        return "identifier"
    if _PERM_ID_RE.match(s):
        return "perm_id"
    return "code"


class ClassifiedId(NamedTuple):
    value: str
    kind: IdentifierKind


def classify(value: str) -> ClassifiedId:
    return ClassifiedId(value=value.strip(), kind=classify_id(value))
```

### Usage in `get_*` methods

`get_object`, `get_collection`, `get_dataset`, `get_project`, `get_space` all accept
a single `str` argument and auto-detect the kind:

```python
def get_object(self, id: str) -> Object | None:
    """Accepts a perm_id ('20240101-1'), identifier ('/SPACE/PROJ/CODE'), or code."""
    cid = classify(id)
    # Build the appropriate SearchCriteria based on cid.kind
    ...
```

The `_type_for_id` internal function (currently in `pybis.py`) moves to
`api/rpc.py` as a private helper that maps `ClassifiedId + entity` → JSON-RPC
id payload. The entity-type-specific `@type` strings (e.g.
`as.dto.sample.id.SamplePermId` vs `as.dto.sample.id.SampleIdentifier`) remain
in `api/rpc.py` — they are transport-layer details, not public API.

### In `search_*` TypedDicts: collapse to single `id` param

Replace the three separate params `perm_id`, `identifier`, `code` in
`BaseEntitySearchParams` with a single optional `id: str` that auto-detects:


## Phase 9 – Filter System

### Problem

The current codebase encodes search operators as magic string prefixes embedded
in property values: `">= 5"`, `"< 2024-01-01"`, `"*wildcard*"`.
This is untyped, fragile, and undiscoverable.

### Actual openBIS search operators (from source audit)

```
String:  StringEqualToValue, StringStartsWithValue, StringGreaterThanOrEqualToValue,
         StringLessThanOrEqualToValue  [+ useWildcards flag for * patterns]
Number:  NumberEqualToValue, NumberGreaterThanValue, NumberGreaterThanOrEqualToValue,
         NumberLessThanValue, NumberLessThanOrEqualToValue
Date:    DateEqualToValue, DateLaterThanOrEqualToValue, DateEarlierThanOrEqualToValue
Any:     AnyStringValue  (matches anything — used for "property exists" checks)
```

Missing in current pybis but present in openBIS v3 API (implement these):
- `StringContainsValue`
- `StringEndsWithValue`

### Solution: `api/filters.py`

```python
from __future__ import annotations
from dataclasses import dataclass, field
from datetime import datetime
from typing import Literal, Any

# Internal mapping to openBIS @type strings
_OP_TO_RPC: dict[str, str] = {
    "eq":           "as.dto.common.search.StringEqualToValue",
    "contains":     "as.dto.common.search.StringContainsValue",
    "starts_with":  "as.dto.common.search.StringStartsWithValue",
    "ends_with":    "as.dto.common.search.StringEndsWithValue",
    "gt":           "as.dto.common.search.NumberGreaterThanValue",
    "gte":          "as.dto.common.search.NumberGreaterThanOrEqualToValue",
    "lt":           "as.dto.common.search.NumberLessThanValue",
    "lte":          "as.dto.common.search.NumberLessThanOrEqualToValue",
    "number_eq":    "as.dto.common.search.NumberEqualToValue",
    "date_eq":      "as.dto.common.search.DateEqualToValue",
    "date_after":   "as.dto.common.search.DateLaterThanOrEqualToValue",
    "date_before":  "as.dto.common.search.DateEarlierThanOrEqualToValue",
    "any":          "as.dto.common.search.AnyStringValue",
}

FilterOperator = Literal[
    "eq", "contains", "starts_with", "ends_with",
    "gt", "gte", "lt", "lte", "number_eq",
    "date_eq", "date_after", "date_before",
    "any",
]

@dataclass(frozen=True)
class PropertyFilter:
    """Typed filter for a single property. Use factory functions below."""
    operator: FilterOperator
    value: Any = None
    use_wildcards: bool = False

    def to_rpc(self) -> dict:
        """Serialize to openBIS JSON-RPC search value dict."""
        base: dict = {"@type": _OP_TO_RPC[self.operator]}
        if self.value is not None:
            base["value"] = self.value
        if self.use_wildcards:
            base["useWildcards"] = True
        return base


# --- Public factory functions ---

def eq(value: str) -> PropertyFilter:
    """Exact string match."""
    return PropertyFilter("eq", value)

def contains(value: str) -> PropertyFilter:
    """Property value contains substring."""
    return PropertyFilter("contains", value)

def starts_with(value: str) -> PropertyFilter:
    """Property value starts with prefix."""
    return PropertyFilter("starts_with", value)

def ends_with(value: str) -> PropertyFilter:
    """Property value ends with suffix."""
    return PropertyFilter("ends_with", value)

def wildcard(pattern: str) -> PropertyFilter:
    """Wildcard pattern using '*' (any sequence) and '?' (single char)."""
    return PropertyFilter("eq", pattern, use_wildcards=True)

def gt(value: int | float) -> PropertyFilter:
    """Numeric greater-than."""
    return PropertyFilter("gt", value)

def gte(value: int | float) -> PropertyFilter:
    """Numeric greater-than-or-equal."""
    return PropertyFilter("gte", value)

def lt(value: int | float) -> PropertyFilter:
    """Numeric less-than."""
    return PropertyFilter("lt", value)

def lte(value: int | float) -> PropertyFilter:
    """Numeric less-than-or-equal."""
    return PropertyFilter("lte", value)

def number_eq(value: int | float) -> PropertyFilter:
    """Exact numeric match."""
    return PropertyFilter("number_eq", value)

def date_eq(value: datetime | str) -> PropertyFilter:
    """Exact date match. Accepts datetime or ISO date string."""
    return PropertyFilter("date_eq", _coerce_date(value))

def date_after(value: datetime | str) -> PropertyFilter:
    """Date on or after value."""
    return PropertyFilter("date_after", _coerce_date(value))

def date_before(value: datetime | str) -> PropertyFilter:
    """Date on or before value."""
    return PropertyFilter("date_before", _coerce_date(value))

def any_value() -> PropertyFilter:
    """Matches any non-null property value (property exists check)."""
    return PropertyFilter("any")

def _coerce_date(value: datetime | str) -> str:
    if isinstance(value, datetime):
        return value.strftime("%Y-%m-%d %H:%M:%S")
    return value
```

## Phase 10 – TypedDict Harmonization

### Problem

Common parameters (`count`, `start_with`, `tags`, `properties`, `registration_date`,
`modification_date`, `registrator`, `modifier`) are repeated in every entity-specific
TypedDict with no shared base, no consistent defaults, and no enforcement.

```
BaseSearchParams
```

## Phase 11 – Property Value Types & Array Types

### Problem

The current `PropertyBag` stores everything as `str` or `list`, with no Python-native
type coercion. Array types (`ARRAY_INTEGER`, `ARRAY_REAL`, `ARRAY_STRING`) exist in
the source but `ARRAY_TIMESTAMP` and `JSON` are missing. The `DataType` Literal in
`types/literals.py` must match what the server actually uses.

### Canonical `DataType` Literal

Cross-referenced against the openBIS v3 AS API and the pybis property.py source:

```python
DataType = Literal[
    # Scalar
    "INTEGER",
    "REAL",
    "BOOLEAN",
    "VARCHAR",
    "MULTILINE_VARCHAR",
    "HYPERLINK",
    "XML",
    "TIMESTAMP",
    "DATE",
    "CONTROLLEDVOCABULARY",
    "SAMPLE",                  # object link property
    "MATERIAL",                # legacy
    # Array (openBIS ≥ 20.10)
    "ARRAY_INTEGER",
    "ARRAY_REAL",
    "ARRAY_STRING",            # note: NOT ARRAY_VARCHAR — this is the actual API name
    "ARRAY_TIMESTAMP",
    # Structured
    "JSON",                    # openBIS ≥ 3.5
]
```

### `PropertyValue` union type (`types/values.py`)

```python
from __future__ import annotations
from datetime import datetime, date
from typing import Any

# Scalar property values
ScalarPropertyValue = str | int | float | bool | datetime | date | None

# Array property values (ARRAY_* types)
ArrayPropertyValue = (
    list[int]       # ARRAY_INTEGER
    | list[float]   # ARRAY_REAL
    | list[str]     # ARRAY_STRING
    | list[datetime]  # ARRAY_TIMESTAMP
)

# Structured
JsonPropertyValue = dict[str, Any] | list[Any]  # JSON type

# Union of all possible property values
PropertyValue = ScalarPropertyValue | ArrayPropertyValue | JsonPropertyValue
```

### `PropertyBag` type-aware coercion

The `PropertyBag.__setitem__` must coerce Python values to the correct format
for the openBIS JSON-RPC payload, based on the property's `DataType`:

| `DataType`         | Python input accepted            | JSON-RPC serialization      |
|--------------------|----------------------------------|-----------------------------|
| `INTEGER`          | `int`                            | `str(value)`                |
| `REAL`             | `int \| float`                   | `str(value)`                |
| `BOOLEAN`          | `bool`                           | `"true"` / `"false"`        |
| `VARCHAR`          | `str`                            | as-is                       |
| `TIMESTAMP`        | `datetime \| str`                | `"YYYY-MM-DD HH:MM:SS"`     |
| `DATE`             | `date \| datetime \| str`        | `"YYYY-MM-DD"`              |
| `CONTROLLEDVOCAB…` | `str` (validated against terms)  | uppercased code             |
| `SAMPLE`           | `str \| Object`                  | perm_id string              |
| `ARRAY_INTEGER`    | `list[int]`                      | `[1, 2, 3]` (JSON array)    |
| `ARRAY_REAL`       | `list[float]`                    | `[1.0, 2.0]`                |
| `ARRAY_STRING`     | `list[str]`                      | `["a", "b"]`                |
| `ARRAY_TIMESTAMP`  | `list[datetime \| str]`          | `["YYYY-MM-DD HH:MM:SS", …]`|
| `JSON`             | `dict \| list` (any JSON-serial) | JSON-serialized string      |

`PropertyBag.__getitem__` must **deserialize** in the opposite direction:
return `list[int]` for `ARRAY_INTEGER`, `datetime` for `TIMESTAMP`, etc.

### Version guard for array and JSON types

```python
# In PropertyBag.__setitem__, before sending array/JSON values:
if data_type.startswith("ARRAY_") or data_type == "JSON":
    self._client._require_version(3, 1, f"Property type {data_type!r}")
```

## Phase 12 – openBIS Version Compatibility

### Problem

Some features (array properties, validation plugins, JSON type, project-level objects)
are version-gated. Currently `is_version_greater_than(major, minor)` exists on
`ServerInformation` but is used ad-hoc with no consistent pattern.

### Solution: `@requires_version` decorator + `ServerInformation` wrapper

```python
# In client.py / auth.py

from functools import wraps
from typing import Callable, TypeVar, ParamSpec

P = ParamSpec("P")
R = TypeVar("R")

def requires_version(major: int, minor: int, feature: str = "") -> Callable:
    """Decorator that raises FeatureNotAvailableError if server version is too old."""
    def decorator(fn: Callable[P, R]) -> Callable[P, R]:
        @wraps(fn)
        def wrapper(self: "Openbis", *args: P.args, **kwargs: P.kwargs) -> R:
            if not self.server_info.is_version_gte(major, minor):
                v = self.server_info.version_str
                msg = f"{feature or fn.__name__!r} requires openBIS ≥ {major}.{minor}, server is {v}"
                raise FeatureNotAvailableError(msg)
            return fn(self, *args, **kwargs)
        return wrapper
    return decorator
```

Add `FeatureNotAvailableError(PybisError)` to `exceptions.py`.

### `ServerInformation` — clean wrapper (`entities/server.py`)

```python
@dataclass(frozen=True)
class ServerVersion:
    major: int
    minor: int

    def __ge__(self, other: ServerVersion) -> bool: ...
    def __str__(self) -> str: return f"{self.major}.{self.minor}"

@dataclass
class ServerInformation:
    version: ServerVersion
    project_samples_enabled: bool
    archiving_configured: bool
    personal_access_tokens_enabled: bool

    def is_version_gte(self, major: int, minor: int) -> bool:
        return self.version >= ServerVersion(major, minor)

    @classmethod
    def from_rpc(cls, payload: dict) -> ServerInformation: ...
```

### Feature flags table

Document in `MIGRATION_GUIDE.md` (and enforce in code):

| Feature                        | Required version | Guard                          |
|--------------------------------|------------------|--------------------------------|
| Array property types           | ≥ 20.10.x / 3.1  | `@requires_version(3, 1)`      |
| JSON property type             | ≥ 3.5            | `@requires_version(3, 5)`      |
| Validation plugins             | ≥ 3.3            | `@requires_version(3, 3)`      |
| Project-level objects          | server flag      | `project_samples_enabled`      |
| Personal access tokens         | ≥ 3.3            | `@requires_version(3, 3)`      |

When a feature requires a server flag (not just a version), raise
`FeatureNotAvailableError` with a clear message explaining what must be enabled.

## Hard Constraints

| Constraint | Reason |
|---|---|
| No `StrEnum` | Use `Literal` for user-facing params |
| No `Optional` / `Union` | Use `X \| None` / `X \| Y` |
| No `Any` outside `rpc.py` | Annotate JSON explicitly as `JsonPayload = dict[str, Any]` |
| No old vocabulary outside `_compat.py` | Sample/Experiment/SampleType/ExperimentType forbidden in all other files |
| No `only_data` / `raw_response` / `use_cache` in public API | Implementation details |
| No bare `**kwargs` in public methods | Explicit keyword args or `Unpack[TypedDict]` only |
| No implementation in `__init__.py` | Only `__all__` and re-exports |
| All public symbols in `__all__` | Explicit public surface |
| `_compat.py` must `DeprecationWarning` on every shim | No silent compat |
| Entity equality based on `perm_id` | Consistent set/dict behavior |
| `search_*` returns `SearchResult[T]`, not `list[T]` | Preserve `total_count` for pagination |
| No magic string operators (`">= 5"`, `"*foo*"`) in `properties` dict | Use `Filter` objects; plain `str` = exact match |
| Array types use `ARRAY_STRING` not `ARRAY_VARCHAR` | Match actual openBIS API name |
| `PropertyBag` coerces types bidirectionally | Python types ↔ JSON-RPC payload (see Phase 11 table) |
| `@requires_version` on all version-gated features | Fail fast with `FeatureNotAvailableError` |
| `classify_id()` used in every `get_*` single-entity method | Never require caller to distinguish perm_id/identifier/code |
| `hierarchy_properties` filter uses `parent_prop()`/`child_prop()` helpers | No string prefix magic |
